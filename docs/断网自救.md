# 出站阻断应急接管手册

**故障特征：物理链路正常，但外部站点与 Claude 服务不可达。**

代理端口失活后，出站熔断器已按预期触发 fail-closed 阻断。按以下步骤执行人工接管。

## 1. 解除熔断

```bash
sudo launchctl bootout system /Library/LaunchDaemons/local.ip-please.guard.plist 2>/dev/null
sudo /sbin/pfctl -a ip-please-guard -F rules 2>/dev/null
touch ~/.ip-please-pause
```

注：`No ALTQ support in kernel` 为 pfctl 标准提示，无需处理。

## 2. 验证出站恢复

```bash
curl -s --max-time 8 https://api.ipify.org; echo
```

返回公网 IP 即表示出站恢复（当前为直连状态，已暴露真实出口）。

## 3. 恢复代理

检查客户端并确认三项生效：

1. 核心转发进程处于运行态
2. 系统代理已启用
3. TUN 已接管流量

## 4. 复检

```bash
ip-please doctor
```

## 5. 重新激活熔断器

```bash
rm -f ~/.ip-please-pause
sudo launchctl bootstrap system /Library/LaunchDaemons/local.ip-please.guard.plist
```

## 熔断器不会重启代理

熔断器只做两件事：代理失活时阻断 web 出站；代理回来后在 5 秒内清空规则。它**不会**启动或重启代理客户端——那属于客户端职责。

想让它顺手拉起客户端，在 `config.sh` 里设置：

```bash
RELAUNCH_APP="FlClash"      # 留空 = 不拉起（默认）
```

然后重跑 `./install.sh`（或直接把 `GUARD_RELAUNCH_APP=FlClash` 写进 `/etc/ip-please/guard.conf`）。每次阻断只尝试拉起一次，不会循环。

## 无 sudo 的完整演练

```bash
ip-please guard test-soft      # 约 3 分钟：停客户端 → 等宽限 → 验证阻断 → 自动拉起 → 验证恢复
```

中途 Ctrl-C 会自动拉起客户端并写入豁免标记，不会把你锁住。

## 运维规程

变更代理配置前必须执行 `ip-please guard pause`；`ip-please doctor` 验证通过后再执行 `ip-please guard resume`。

## 直连窗口内

严禁启动 Claude.app 或访问 claude.ai：该窗口内的请求会以真实出口身份发送至服务端并留存记录。

## 熔断器边界

| 项 | 值 |
|---|---|
| 判定依据 | `127.0.0.1:${PROXY_PORT}` 的 TCP 连通性 |
| 宽限 | 120 s |
| TTL 回退 | 阻断持续 900 s 后自动放行 3600 s |
| 阻断面 | TCP 80/443/8080/8443，UDP 443/3478/5349/19302 |
| 豁免入口 | `~/.ip-please-pause`、`/etc/ip-please/pause`；写入标记同时重置冷却计时器 |
| 自愈 | pf anchor 缺失时自动补注册；核对规则条数，异常只写系统日志 |

## 状态查询

```bash
sudo pfctl -a ip-please-guard -sr    # 含 block 规则 = 已阻断；为空 = 待命
sudo launchctl print system/local.ip-please.guard | head -5
```
